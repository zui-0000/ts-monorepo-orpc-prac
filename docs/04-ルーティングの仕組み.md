# ルーティングの仕組み

frontend は TanStack Router のファイルベースルーティングで動く。**経路をファイルで
表し、型をそこから生成する。** ここではフォルダの構成、起動から描画までの経路、
生成物の扱いをまとめる。

React Router ではなくこれを選んだ理由は
[ライブラリ関連/ADR-04](./adr/ライブラリ関連/ADR-04-ルーターにTanStackRouterを採用.md)
にある。

## フォルダ構成

```txt
src/
├── main.tsx           起動。#root に App を描く
├── App.tsx            ルーターと QueryClient を組む。型の登録もここ
├── routeTree.gen.ts   自動生成。手で触らない
├── routes/            経路の宣言だけを置く
│   ├── __root.tsx     根。RouterContext の定義と共通レイアウト
│   ├── index.tsx      /
│   ├── sign-in.tsx    /sign-in
│   └── sign-up.tsx    /sign-up
└── components/
    ├── layouts/       RootLayout
    └── pages/         画面の本体
```

**`routes/` には経路以外を置かない。** ファイル名がそのまま URL になる仕組みのため、
対応しないものが混ざるとツリーが読めなくなる。置いた場合に何が起きるかは後述する。

**画面の本体は `components/pages/` に置く。** `routes/` へは下ろさない。経路の宣言と
画面の中身を分けたまま保つ方針である。

## 経路が増えたとき

**フラットとフォルダは等価で、混ぜられる。** `user.$userId.tsx` と
`user/$userId.tsx` は同じ経路になる。公式も「100% どちらか一方が最適なことはまず
無い」として混在を薦めている。

**`index.tsx` は Next.js と意味が違う。** フォルダ自身の経路を作るのは `route.tsx`
であり、`index.tsx` は**親の経路に完全一致したとき**だけ当たる子である。

| 置き方             | 当たる URL         |
| ------------------ | ------------------ |
| `user/route.tsx`   | `/user` (子を包む) |
| `user/index.tsx`   | `/user` ちょうど   |
| `user/$userId.tsx` | `/user/$userId`    |

**中間にルートファイルは要らない。** `user/edit/index.tsx` だけ置けば `/user/edit`
ができる。

**フォルダにする理由ができるのは、中に 2 枚目が入るときである。** ファイル 1 枚を
フォルダへ入れても階層が 1 段深くなるだけで、得るものが無い。

```txt
routes/
├── index.tsx
├── sign-in.tsx              ぶら下がるものが無いので 1 枚のまま
└── user/
    ├── edit/
    │   ├── index.tsx        /user/edit
    │   └── -EditForm.tsx    このページ専用の部品。- でツリーから外れる
    └── $userId.tsx          /user/$userId
```

### ID にだけ末尾スラッシュが付く

フォルダ + `index.tsx` にすると**ルート ID の形が変わる。** `Link` の `to` は変わら
ない。

| 置き方              | ID          | `to`       |
| ------------------- | ----------- | ---------- |
| `sign-in.tsx`       | `/sign-in`  | `/sign-in` |
| `sign-in/index.tsx` | `/sign-in/` | `/sign-in` |

ID を直に書くのは `getRouteApi()` だけなので、影響はそこに限られる。**型で弾かれる**
ため直し忘れても気づける。

### ガードを共有したくなったら

`_` 接頭辞のルートは **URL に現れないのに親として振る舞う。** 認証の判定を 1 回だけ
書きたいときに使う。

```txt
routes/
├── _authed.tsx        セッション必須。ガードはここに 1 回だけ
└── _authed/
    └── index.tsx      / (URL に _authed は出ない)
```

**親の `beforeLoad` は子より先に走り、そこで投げれば子は読み込まれない。** 現状は
`sign-in.tsx` と `sign-up.tsx` が同じ判定を持っているため、経路が増えたらこの形へ
移す。

## 呼び出し経路

起動から描画まではこう流れる。

```txt
main.tsx        #root を取る
  └─ App.tsx    QueryClient を作り、createAppRouter へ渡す
       └─ createRouter({ routeTree, context: { queryClient } })
            └─ routeTree.gen.ts   routes/*.tsx を束ねたもの
                 └─ __root.tsx → index.tsx / sign-in.tsx / sign-up.tsx
```

**`queryClient` は React の外へ渡している。** 経路の `beforeLoad` は描画の前に走るため
フックが使えない。だから同じ実体を `context` として注ぎ込む。

```tsx
// App.tsx
const [router] = useState(() => createAppRouter(queryClient));
```

### 1 つの経路で起きること

`/` を例にする。**上から順に走り、途中で投げれば以降は動かない。**

```ts
// routes/index.tsx
export const Route = createFileRoute("/")({
  beforeLoad: async ({ context }) => {
    const session = await context.queryClient.query({ ...getSessionQueryOption, staleTime: "static" });
    if (!session) throw redirect({ to: "/sign-in" });
    return { userId: session.user.id };
  },
  loader: ({ context }) =>
    context.queryClient.query({ ...getUserQueryOption(context.userId), staleTime: "static" }),
  component: ProfilePage,
});
```

| 段           | 役割                                              |
| ------------ | ------------------------------------------------- |
| `beforeLoad` | 入ってよいかを決める。親から順に 1 つずつ走る     |
| `loader`     | 描画に要るものを取る。`beforeLoad` が通った後だけ |
| `component`  | 描く                                              |

**`beforeLoad` の戻り値は context に合流する。** 上の例では `userId` を足しており、
`loader` は `context.userId` を型付きで読める。**入れ忘れれば `loader` が型エラーに
なる。** これが React Router との差で、あちらは鍵ごとの `get` / `set` になる。

経路はもう 1 つ `validateSearch` を持てる。`sign-in.tsx` が使っており、
`?registered=true` を真偽値として受け取るために置いている。

## routeTree.gen.ts

**`@tanstack/router-plugin` が `routes/` を走査して吐く。** dev サーバの起動時と
ビルド時に作り直される。

```ts
// vite.config.ts
tanstackRouter({ target: "react", autoCodeSplitting: true });
```

設定を渡していないため、生成器の既定値で動いている。

| 設定                    | 既定値                   |
| ----------------------- | ------------------------ |
| `routesDirectory`       | `./src/routes`           |
| `generatedRouteTree`    | `./src/routeTree.gen.ts` |
| `routeFileIgnorePrefix` | `-`                      |

**置き場所は `generatedRouteTree` で変えられる**が、変えていない。既定のままなら
設定を持たずに済み、世の情報もすべて既定値を前提にしているため。

### 根は `__root.tsx` でなければならない

**この 1 枚だけは必須で、名前も変えられない。** 生成器に定数で埋まっており、設定項目
が存在しない。

```ts
var rootPathId = "__root";
```

`routes/` から消すとビルドが落ちる。

```txt
Error: rootRouteNode must not be undefined.
Make sure that you add a "__root.tsx" file to your routes directory.
```

木を組む以上、根を宣言する誰かが要るためである。生成された `routeTree.gen.ts` を見る
と、すべての経路が `getParentRoute: () => rootRouteImport` を持っている。

**必須なのは存在だけで、中身は縛られていない。** 現状は 4 つ書いているが、要るのは
ルートを export することだけである。

| 書いているもの                                | 必須か                                                  |
| --------------------------------------------- | ------------------------------------------------------- |
| `createRootRouteWithContext<RouterContext>()` | 必須。context が要らなければ `createRootRoute()` でよい |
| `component: RootLayout`                       | 任意。省くと `<Outlet />` だけが描かれる                |
| `notFoundComponent: NotFoundPage`             | 任意                                                    |
| `RouterContext` の定義                        | 任意。使う場所と揃えるためここに置いた                  |

なおこの規約はファイルベースルーティングのものである。`createRoute()` で木を手で組む
コードベースルーティングは `routes/` を走査しないため、`__root.tsx` という名前の縛りも
無い。

### git に入れる。lint と整形からは外す

生成物だが**コミットする。** 型検査がこれを読むため、ビルドしていない環境で
`tsc --noEmit` が落ちないようにするには必要になる。

一方で lint と整形からは外してある。整形しても次の生成で書き戻されるだけだからで、
ファイル自身の冒頭にもそう書かれている。

```jsonc
// .oxlintrc.jsonc
"ignorePatterns": ["src/routeTree.gen.ts", "public/mockServiceWorker.js"]
```

```txt
# .prettierignore (oxfmt が読む)
**/routeTree.gen.ts
```

### 経路以外を置くとどうなるか

**警告が出る。** 走査は `-` と `.` で始まるもの以外の `.ts` / `.tsx` をすべて拾い、
`Route` を export していないファイルを見つけると知らせてくる。

```txt
Warning: Route file ".../routes/create-router.ts" does not export a Route.
This file will not be included in the route tree.
  1. Rename the file to ".../routes/-create-router.ts" (prefix with "-")
```

**この警告は普段見えない。** プラグインが mtime でキャッシュしており、一度通った
ファイルは再走査しないためである。確かめるには触ってから作り直す。

```zsh
$ touch src/routes/*.tsx && pnpm exec vite build
```

放置すると、**本物の経路で `Route` の export を書き忘れたときに、その警告が埋もれる。**
どうしても `routes/` の中に置きたいものは `-` を付けて外す。付けたものは
ツリーに入らないので、そのページ専用の部品を同じ階層へ置くときに使える。

## 型が効く仕組み

`Link` や `useNavigate` の `to` が既知の経路だけを受け付けるのは、**ルーターの型を
`Register` に登録している**ためである。

```tsx
// App.tsx
declare module "@tanstack/react-router" {
  interface Register {
    router: ReturnType<typeof createAppRouter>;
  }
}
```

効いているかは壊せば分かる。存在しない経路を書くと、既知の経路の union から外れる。

```txt
error TS2820: Type '"/sign-uppp"' is not assignable to type
'"." | ".." | "/" | "/sign-in" | "/sign-up"'. Did you mean '"/sign-up"'?
```

**この登録を `.d.ts` に書かないこと。** `skipLibCheck` が有効なため `.d.ts` は
型検査されず、参照先を改名しても壊れたまま気づけない。`Link` の型安全だけが静かに
消える。`.tsx` や `.ts` に置いておけば検査される。

## コード分割

`autoCodeSplitting: true` により、経路の設定が 2 つに分かれて配置される。

| 区分           | 中身                                                             | 置き場所   |
| -------------- | ---------------------------------------------------------------- | ---------- |
| クリティカル   | `beforeLoad` / `loader` / `validateSearch` / context             | 本体に残る |
| 非クリティカル | `component` / `errorComponent` / `pendingComponent` などの描画物 | 別チャンク |

画面は経路ごとに別チャンクへ出ている。

```txt
dist/assets/sign-in-*.js   2.93 kB │ gzip: 1.44 kB
dist/assets/sign-up-*.js   3.37 kB │ gzip: 1.57 kB
```

**手で `React.lazy()` を書く必要は無い。** 切り出したい対象である画面のコンポーネント
は非クリティカル側として既に分かれており、重ねると二重になる。

**`loader` は分けない。** ローダーは元々非同期の境界であるため、分けると「チャンクの
取得」と「ローダーの実行」を二重に待つことになる。しかも先読みで最も効く資産である。
`defaultPreload: "intent"` でリンクに触れた時点の先読みが効くのは、クリティカル側が
本体に残っているおかげである。

**コードベースルーティングでは自動分割が効かない。** `createRoute({ getParentRoute })`
で経路を組む書き方は、プラグインの走査対象が `routes/` のファイルであるため対象外に
なる。あちらは手で `lazy()` する必要がある。
